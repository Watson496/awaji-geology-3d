# 検査の実行

ビューアやモデルを変更したあとの、実装とデータの整合性を調べる検査手順です。コマンドはリポジトリのルートで実行します。

## Web側の検査

Node環境を用意した状態で、幾何処理のテストと型検査を含むビルドを実行します。

```sh
npm run test:geometry
npm run build
```

## モデルの検査

[計算環境](regenerate-model.md)と元資料を準備した状態で、Pythonのテストとデータ検査を実行します。元資料を読む検査もあるため、生成済みのWebデータだけでは全検査を実行できません。

```sh
npm test
npm run validate
```

検査では原記号・色、構造と原区分の所属、断層を跨がない区間の累重順序、断層による補間の遮断、公式断層の全頂点が原データと一致すること、資料の近さの属性で岩体を切り落とさないこと、標高−300mにも連続した原区分の推定が残ること、任意断面の交差、原断面の境界/断層との距離、数値解の残差を確認します。`web/data/<scenario>/section-validation.json` の距離は、拘束に使った断面の再現診断です。現状の基準モデルでは地質境界3点との距離は約85〜220mです。検査結果の解釈は[モデルの読み方と限界](../explanation/model-and-limits.md#比較モデルと検証)に記載しています。

## ブラウザでの検査

`npm start` を別の端末で起動した状態で、次のコマンドを実行します。このスクリプトはPlaywrightとChromeを使います。

```sh
node scripts/check-browser.mjs
```

このスクリプトはローカルのルートパスを対象にします。GitHub Pagesのサブパスでの確認手順は[リリース手順](release.md)に記載しています。
