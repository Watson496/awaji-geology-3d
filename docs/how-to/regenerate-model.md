# モデルデータの再生成

入力資料や推定条件を変更した場合に、表示データを作り直す手順です。リポジトリの取得とNode環境の準備は[ローカルでの起動](local-development.md)に従います。モデルの計算には、uvとPython 3.12も必要です。

## 計算環境

リポジトリのルートで依存パッケージを準備します。

```sh
uv sync --locked
```

## 入力データとモデル

元資料を取得し、地表データ、活断層図、地下モデルの順に生成します。

```sh
npm run data
uv run python scripts/prepare_active_fault_map.py
npm run model
npm run validate
```

`npm run model` は、GemPyによる事前場の計算、断層・構造・断面・海域の制約の適用、表示メッシュの生成、表示用断層線の統合を行います。事前場のキャッシュは、入力ハッシュが一致する場合だけ再利用します。元資料の取得に失敗した場合は処理を停止します。

## 表示データのみの再生成

推定済みの地質区分を変えず、岩体名の帰属や表示メッシュを更新する場合は、次のコマンドを使います。

```sh
npm run mesh
```

断層線の表示統合だけを更新する場合は、次のコマンドを使います。

```sh
npm run fault-display
```

推定地質区分の境界条件を変更した場合は、表示メッシュだけでなく `npm run model` から実行します。

## 生成物の確認

[検査の実行](validation.md)に従い、原凡例、断層、断面との対応を確認します。出典や加工内容を変更した場合は、`web/data/ATTRIBUTION.md` も更新します。生成物の保存先は[データ形式・座標系](../reference/data.md)に記載しています。
